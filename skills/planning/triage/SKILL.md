# Triage

Move tickets through a small state machine of triage roles. `/jkit` invokes this for prompts like "what needs my attention?", "what's ready for agents?" or "look at this bug"; the user may also run it directly.

**Tracker first.** The tracker doc (path in `AGENTS.local.md` or `AGENTS.md`; run `/setup-jkit` if neither names one) says how to query tickets, post comments, set roles, and where out-of-scope records live. `triage-labels.md` maps the canonical roles below to this tracker's strings.

When the tracker doc treats external pull requests as a request surface, triage covers them too: **a PR is a ticket with attached code**, with the deltas marked "for a PR" below.

Start every comment or ticket you post during triage with:

```
> *This was generated by AI during triage.*
```

## Reference docs

- [AGENT-BRIEF.md](AGENT-BRIEF.md) - how to write durable agent briefs
- [OUT-OF-SCOPE.md](OUT-OF-SCOPE.md) - where rejected requests are recorded

## Roles

- **Category** (exactly one): `bug`, `enhancement`.
- **State** (exactly one): `needs-triage`, `needs-info`, `ready-for-agent` (fully specified for an AFK agent), `ready-for-human`, `wontfix`.

For a PR, `ready-for-agent` means a brief is attached and an agent takes the next step on the diff; `ready-for-human` means it's ready for a human to merge.

Transitions: an untriaged ticket goes to `needs-triage`, then to `needs-info`, `ready-for-agent`, `ready-for-human` or `wontfix`. `needs-info` returns to `needs-triage` once the reporter replies. The user can override at any time; when state roles conflict or a transition looks unusual, flag it and ask.

## Show what needs attention

Query the tracker and present three buckets, oldest first, with counts and a one-line summary each:

1. **Untriaged:** never triaged. In `.scratch`, an `open` ticket with no `Type:` line.
2. **`needs-triage`:** evaluation in progress.
3. **`needs-info` with reporter activity** since the last triage notes.

When PRs are in scope, include external PRs (the tracker doc defines external) tagged `[PR]` or `[ticket]`. A collaborator's in-flight PR isn't triage work, but a PR the user names is always triaged. Let the user pick.

## Triage one ticket or PR

1. **Gather context.** Read the full ticket or PR (body, comments, roles, author, dates; for a PR, the diff), including prior triage notes so resolved questions stay resolved. Explore the codebase with the domain glossary and ADRs. Then run two checks:
   - **Redundancy:** search for an existing implementation by domain concept, not just the request's wording, and report where you looked.
   - **Prior rejection:** check the effort's map **Out of scope** and the project's out-of-scope records ([OUT-OF-SCOPE.md](OUT-OF-SCOPE.md)) for a match.
2. **Recommend** a category and state with reasoning and a short codebase summary, including whether it's already implemented. Wait for direction.
3. **Verify the claim.** For a bug, reproduce it from the reporter's steps. For a PR, check it out and run the relevant tests or commands. Report: confirmed (with code path), failed, or insufficient detail (a strong `needs-info` signal).
4. **Grill if needed** with `/grilling` and `/domain-modeling`, a round at a time, updating `CONTEXT.md` and ADRs as decisions land.
5. **Apply the outcome:**
   - `ready-for-agent`: post an agent brief ([AGENT-BRIEF.md](AGENT-BRIEF.md)).
   - `ready-for-human`: the same structure, plus why it can't be delegated (judgment calls, external access, design decisions, manual testing).
   - `needs-info`: post triage notes (template below).
   - `wontfix`, by reason:
     - **Already implemented:** point to where it lives. Record nothing as out of scope.
     - **Rejected bug:** explain politely, then close.
     - **Rejected enhancement:** record it per [OUT-OF-SCOPE.md](OUT-OF-SCOPE.md), link the record from a comment, then close.
   - `needs-triage`: apply the role, with an optional comment on partial progress.

## Quick state override

When the user says "move <ticket> to ready-for-agent", trust them: state the role change, comment or close you're about to make, then act without grilling. When moving to `ready-for-agent` without a grilling session, ask whether they want an agent brief.

## Needs-info template

```markdown
## Triage Notes

**What we've established so far:**

- point 1

**What we still need from you (@reporter):**

- question 1
```

Capture everything resolved during grilling under "established so far". Make each question specific and actionable.

## Resuming

When prior triage notes exist, read them, check whether the reporter answered the outstanding questions, and present an updated picture before continuing.
